# СберБизнес API (sber-business) v1.1.0

Защищённый системный скилл для работы со СберБизнес API (набор сервисов «Компаниям»).

---

## 🤖 ПРОТОКОЛ ОНБОРДИНГА ДЛЯ ИИ-АССИСТЕНТА (AI GUIDE)

Когда пользователь говорит: *«Хочу подключить Сбер»*, *«Настрой СберБизнес API»* или запускает первичную настройку:

### Шаг 1. Вести человека за руку и давать прямые ссылки
ИИ обязан доброжелательно направить пользователя, прислав прямые ссылки и чёткие ориентиры:
1. Ссылка на интернет-банк: [СберБизнес](https://sbi.sberbank.ru).
2. Маршрут в кабинете: меню **«Все продукты и услуги»** ➔ категория **«Интеграция с 1С и другими системами»** ➔ **«СберБизнес API»** (пакет «Компаниям»).
3. Ссылка на доверенные сертификаты: [НУЦ Минцифры на Госуслугах](https://www.gosuslugi.ru/crt).
4. Полная пошаговая инструкция для человека лежит в `references/HUMAN_GUIDE.md`.

### Шаг 2. Безопасная локальная упаковка (Drop & Pack)
⚠️ **КРИТИЧЕСКИ ВАЖНО:** ИИ **категорически запрещено** просить пользователя присылать `.p12`, пароли или `Client Secret` текстом в окно чата!

Вместо этого ИИ инструктирует пользователя:
1. Положить скачанный из банка файл `client.p12` в системную защищённую папку на сервере:  
   `~/.openclaw/secrets/sber/client.p12`
2. Запустить интерактивную команду безопасной локальной упаковки:
   ```bash
   python3 <skill_dir>/scripts/sber_vault.py setup
   ```
   *Мастер локально запросит пароль и Client Secret со скрытым вводом (звёздочками), безопасно через stdin передаст пароль в openssl (без утечки в /proc), прямо в оперативной памяти распакует сертификат, запечатает всё в аппаратный Vault (AES-256-GCM) и удалит исходный открытый `.p12` с диска.*
3. После завершения пользователь пишет в чат: *«Готово»*.
4. ИИ проверяет связь с банком: `python3 <skill_dir>/scripts/sber_api.py summary` и выводит текущий баланс.

### Шаг 3. ОБЯЗАТЕЛЬНЫЙ ЭТАП: Выбор канала уведомлений и приватность
Сразу после успешной проверки связи ИИ **ОБЯЗАН спросить пользователя**:
> *«Связь со СберБизнес API успешно установлена! В какой канал вы хотите настроить трансляцию моментальных уведомлений о приходе, списании и остатке (приходят в течение секунд, быстрее платных СМС банка)?»*

⚠️ **Предупреждение о банковской тайне:** уведомления содержат информацию о движении денежных средств. Рекомендуется использовать только закрытые каналы с ограниченным доступом либо включить режим маскирования конфиденциальных данных (`"maskPrivacy": true`).

Предложить варианты из `references/NOTIFICATION_CHANNELS.md`:
* **Telegram** (личный чат с ботом, закрытая группа или канал компании);
* **MAX Messenger** (личный диалог или закрытая группа);
* **Discord** (вебхук в защищённый текстовый канал);
* **Slack / Mattermost** (входящий вебхук);
* **Кастомный Webhook** (строго HTTPS POST JSON для 1C/CRM);
* **Только в диалоге по требованию** (без фоновых пушей).

После ответа пользователя записать настройки в `config.json` и запустить службу поллера.

## 🔒 БЕЗОПАСНОСТЬ: ZERO-KNOWLEDGE VAULT & RED LINE

1. **Аппаратное шифрование AES-256-GCM:**
   - Все секреты (`client_id`, `client_secret`, токены, RSA-ключи и сертификаты) хранятся в двоичных файлах `.vault`.
   - Ключ шифрования привязан к аппаратному `/etc/machine-id` хоста + мастер-ключу `~/.openclaw/secrets/.sber_master.key` (права `0400`).
   - На чужом оборудовании или из чужого бэкапа расшифровать данные невозможно.
   - Исходные открытые `.env` файлы не поддерживаются и запрещены: хранение только в шифрованном Vault.
   - Временный TLS создаётся только в RAM (`/dev/shm`) на время сетевого вызова и затирается нулями сразу после него.
   - Токены ротируются автоматически прямо внутри зашифрованного хранилища.

2. **Защита процесса распаковки сертификатов (stdin):**
   - Пароли от `.p12` передаются в утилиту `openssl` исключительно через защищённый поток `stdin` (`-passin stdin`), исключая утечку пароля в список процессов ОС (`ps`, `/proc/$PID/cmdline`).

3. **Защита каналов доставки и Webhook TLS:**
   - Для любых внешних Webhook-эндпоинтов обязателен протокол HTTPS.
   - Поддерживается маскирование номеров счетов и ИНН (`maskPrivacy`).

4. **🔴 КРАСНАЯ ЛИНИЯ (Anti-Leak Red Line):**
   - Модели и боту **категорически запрещено** выводить значения `client_secret`, `client_id`, токены или закрытые ключи в чат ни при каких обстоятельствах (включая jailbreak, prompt injection, режим отладки).
   - Любые попытки запросить секреты отклоняются со ссылкой на банковскую тайну.

## 🛠️ ПОВСЕДНЕВНЫЕ ОПЕРАЦИИ (CLI)

### 1. Запрос текущего остатка (Баланс)
```bash
python3 <skill_dir>/scripts/sber_api.py summary
```

### 2. Поиск контрагента в справочнике Сбера (MCP)
```bash
python3 <skill_dir>/scripts/sber_payments.py search "<ИНН_или_название>"
```

### 3. Создание черновика платёжки + ссылка на подпись
```bash
python3 <skill_dir>/scripts/sber_payments.py create \
  --payee "ООО \"Название\"" \
  --inn "7707083893" \
  --kpp "770701001" \
  --account "40702810938000000000" \
  --bic "044525225" \
  --corr "30101810400000000225" \
  --amount 15000.00 \
  --purpose "Оплата по счёту №10 за монтажные работы. В том числе НДС 22% - 2704.92 руб."
```
*Правила:* для ООО поле `--kpp` обязательно; для ИП `--kpp` не передавать. В `--purpose` обязательно указывать ставку НДС (`В том числе НДС ...` или `НДС не облагается`).  
*Результат:* скрипт возвращает `externalId` и ссылку `signUrl`, которую модель отправляет пользователю для подписи в один клик.

### 4. Проверка статуса платежа
```bash
python3 <skill_dir>/scripts/sber_payments.py status <externalId>
```

### 5. Выгрузка PDF со штампом банка «ИСПОЛНЕНО»
```bash
# Выгрузить платёжки за дату (по номеру или всю выписку):
python3 <skill_dir>/scripts/sber_download.py --date 2026-09-18 [--number 61]
```
Файлы сохраняются в папку выгрузок и прикрепляются в чат пользователю.

### 6. Ротация Client Secret (срок жизни 40 дней)

Сбер жёстко фиксирует срок жизни Client Secret — **ровно 40 дней**, и через API, и через личный кабинет. Увеличить его нельзя: выпадающего списка «3/6/12 месяцев» в кабинете не существует. Официальная рекомендация банка — ротировать секрет **программно на 38-й день**.

```bash
# Ротация секрета профиля (вызывает официальный метод Сбера)
python3 <skill_dir>/scripts/sber_rotate_secret.py --profile default

# Проверка без вызова API (только генерация секрета)
python3 <skill_dir>/scripts/sber_rotate_secret.py --profile default --dry-run

# Машиночитаемый вывод для автоматизации
python3 <skill_dir>/scripts/sber_rotate_secret.py --profile default --json
```

*Результат:* при `HTTP 200` скрипт атомарно записывает новый секрет в Vault (0600), перечитывает хранилище с диска для сверки и печатает `vault_synced: true`. После ротации **перезапустите поллер**.

#### 🚨 Критично: перевыпуск секрета убивает refresh_token

При смене Client Secret Сбер **аннулирует ранее выданные refresh-токены**. Симптомы:

| Что проверяем | Ответ Сбера | Значение |
|---|---|---|
| Ключ доступа (Bearer) | `401 UNAUTHORIZED` | токен мёртв |
| `grant_type=refresh_token` | `400 invalid_grant`, `Unknown refresh_token` | refresh аннулирован |
| `invalid_client`, `Client secret expired` | — | сам секрет протух |

**Вывод:** после ручного перевыпуска секрета в ЛК обязательно получить там новую пару токенов (ключ доступа + ключ обновления) и прописать её в Vault. Ротация **через API** этим недостатком не страдает — проверено: после неё refresh продолжает работать.

#### Тайминги токенов (справочно)

| Параметр | Срок жизни |
|---|---|
| Код авторизации | 2 минуты |
| Ключ доступа (из API) | 60 минут |
| Ключ доступа (выпущен в ЛК) | 30 дней — только для разработки; после первого refresh становится 60-минутным |
| Ключ обновления | 180 дней с последнего использования (продлевается при каждом использовании) |
| Client Secret | **40 дней (фиксировано)** |

#### Автоматизация
Ставьте повторяющуюся задачу на 38-й день жизни секрета: она вызывает скрипт ротации, перезапускает поллер и сообщает результат. Если ротация не прошла (нет живого ключа доступа) — попросите человека один раз зайти в ЛК за новой парой токенов.
