# Security audit (host + OpenClaw gateway)

Быстрый read-only аудит нашей машины и шлюза. Ничего не меняет, секретов не печатает.

## Когда использовать

- «проверь хост на дыры», «аудит безопасности», «что у нас торчит наружу»;
- после смены SSH-конфига, firewall, установки Docker-контейнеров;
- раз в месяц как профилактика.

## Запуск

```bash
python3 scripts/audit.py            # обычный отчёт в markdown
python3 scripts/audit.py --json     # машинный вывод
python3 scripts/audit.py --quick    # без сетевых проверок и apt (быстро)
```

Скрипт только читает: конфиги, `ss`, `stat`, `ufw status`, `sshd -T`, `lsblk`, `docker ps`.
Ничего не устанавливает, не правит и не перезапускает.

## Что проверяется

1. **Хост** — ОС, ядро, аптайм.
2. **Gateway** — bind-адрес, включена ли аутентификация, trustedProxies, порт.
3. **Порты** — слушающие сокеты на `0.0.0.0`/`::`, с процессами где видно.
4. **SSH** — `PermitRootLogin`, `PasswordAuthentication`, `Port`, `AllowUsers`.
5. **Firewall** — `ufw status` / `nft` / `iptables` (что доступно без root).
6. **Права** — `~/.openclaw` (ожидается `700`), каталоги агентов, файлы с токенами: не должны быть world-readable.
7. **Секреты в открытом виде** — поиск по workspace шаблонов `api_key=`, `Bearer`, приватных ключей. В отчёт попадают только путь и тип находки, значение маскируется.
8. **Обновления** — сколько пакетов ждёт `apt`, есть ли ядро в списке.
9. **Бэкапы** — дата последнего бэкапа в `~/.openclaw/backups`, предупреждение если старше 14 дней.
10. **Шифрование диска** — наличие `crypto_LUKS` в `lsblk`.
11. **Docker** — контейнеры с `privileged`, публикации портов на `0.0.0.0`, `network_mode: host`.
12. **Fail2ban** — активна ли служба.

## Формат отчёта

Уровни: 🔴 CRITICAL, 🟠 HIGH, 🟡 MEDIUM, 🔵 INFO. В конце — счётчики и список приоритетных действий.

## Правила

- Не предлагать auto-fix: изменения обсуждаются отдельно и делаются по одному.
- Не выводить значения токенов, ключей и паролей — только путь и тип.
- Если проверка недоступна без root, писать «требует sudo», а не падать.
- Перед правкой SSH/firewall сначала подтвердить запасной путь доступа.
